[Introduction]

Fahh Editor docs

A desktop code editor built on Tauri 2, Rust, React 18 and Monaco. It plays fahh.mp3 when a language server reports an error, at most once per cooldown window.

The sound is src-tauri/assets/fahh.mp3, and src/lib/fahh.ts loads it by that exact name. Renaming the file silences the editor.

Status in v0.3.0

Works

File tree, Monaco editor with tabs, terminal, Run panel, Git sidebar, AI panel, themes, extensions list, optional-tools installer, and diagnostics from language servers with the sound.

In progress

Completion, hover and go-to-definition from language servers (the replies are received but not yet shown), and the step-through debugger (the panel and commands exist; event handling is incomplete).

Useful for UI work. The interface loads in a normal browser, but anything that calls the Rust backend (files, terminal, Git, language servers) will not work there.

pnpm test           # Vitest unit tests
[Architecture]

Two processes, one contract

The Rust backend owns the operating system: files, processes, language servers, Git. The React front end owns the interface. They talk over Tauri IPC: the front end calls commands with invoke(), and the backend pushes events the front end receives with listen(). The shared payload types live in src/lib/types.ts, which the Rust structs follow.

[The sound]

From diagnostic to sound

The whole path, in order. You can watch steps 3 to 5 happen in the simulator.

  1. The language server publishes. lsp_client.rs relays textDocument/publishDiagnostics to the window as lsp://message.
  2. LspBridge draws. The diagnostics become Monaco markers. An empty list clears the file.
  3. Is any of them an error? Severity 1, or a missing severity, which the LSP specification says to treat as the most severe. Warnings, information and hints stop here.
  4. Is the cooldown ready? One module-level cooldown for the life of the app. A refused call does not extend the window.
  5. trigger_error_sound. The command reaches ErrorDetector, which applies the same cooldown on the Rust side and emits fahh://error.
  6. fahh.ts plays. The buffer decoded at start-up goes to an AudioBufferSourceNode, so there is no loading delay.

[Configuration]

~/.fahh/config.json

Created on first run and safe to edit by hand. Every field is optional.

{
  "sfx_cooldown_secs": 3,
  "installed_tools": ["gh"],
  "last_workspace": "/path/to/project",
  "theme": null
}
FieldMeaning
sfx_cooldown_secsSeconds between sounds. Default 3 when the field is missing; 0 plays on every error.
installed_toolsTools installed through the wizard.
last_workspaceStored, but not yet used to reopen a folder at start-up.
themeReserved. The theme you pick is currently kept in the app's local storage.

[Optional tools]

The installer wizard

Open it from the gear button at the bottom of the activity bar. It checks which tools are already on your PATH, then runs the install command you choose on your own machine, with progress streamed as it goes.

The wizard also offers one AI coding assistant's command-line tool, installed with npm.

Building and packaging

pnpm tauri build                 # all bundle targets for this OS
cd src-tauri && cargo test       # Rust unit tests
cargo clippy --all-targets -- -D warnings   # the CI lint gate

Bundles land in src-tauri/target/release/bundle/. The v0.3.0 release was built into:

PlatformFiles
Windows_x64-setup.exe (NSIS), _x64_en-US.msi
macOS_aarch64.dmg, _x64.dmg, and .app.tar.gz for each
Linux_amd64.AppImage, _amd64.deb, x86_64.rpm

App identifier com.fahh.editor, default window 1400 × 900. Everything runs locally; there is no server and no account.
